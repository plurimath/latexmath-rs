# latexmath Rust raw parser

Local unpublished Rust package using the upstream shared PARG artifact and declared
Rust bindings; no handwritten grammar. `Parser::new()` verifies embedded checksums.

```rust
let parser = latexmath::Parser::new()?;
let parsed = parser.parse("x+1")?;
println!("{}", parsed.canonical());
# Ok::<(), latexmath::Error>(())
```

`parse_with_decimal(input, decimal)` accepts `.`, `,`, and `٫`. The native
Parsanol engine uses the immutable source candidate recorded in `UPSTREAM.json`. Unicode preprocessing and stage transforms
are reused from the pinned shared testsuite, with attribution in UPSTREAM.json.
Errors preserve the native error and expose UTF-8 byte offsets relative to the
preprocessed grammar input. Parsed slices reference `parsed_input`; caller offsets
are not inferred after preprocessing. Canonical output includes character offsets.

The default API exposes raw stage trees and bound JSON. Optional `models` uses
33 types and JSON codecs generated by the existing upstream Lutaml Rust
PR #8 generator. `Parser::parse_model(input, decimal)` and
`typed::to_portable_json(model)` are implemented; their native construction and version-1 C ABI were exercised with focused local checks. Optional `ffi`
exports the stage-specific version-1 C ABI declared in `include/latexmath.h` for
portable model JSON consumers. The ABI returns portable model JSON and structured errors; free each result once as documented in the header.

No full typed parity, Plurimath facade or math-writer coverage is claimed.
Raw and typed verification are assessed separately.
Use `cargo run --example parse -- 'x+1'` for the raw API and
`cargo run --features models --example model -- 'x+1'` for typed models once built.

Native refusal offsets use the Rust engine's farthest-error position and may differ
from Ruby's deepest-error selection. Offsets refer to the preprocessed grammar
input; caller-coordinate remapping is not inferred.

The declared writer omits empty/nil members. Model identity and wire idempotence
across JSON read/write are not guaranteed; cross-runtime model equivalence remains
a separate verification boundary.

`Parser::parse_legacy(input)` and `parse_legacy_with_decimal(input, decimal)`
expose the legacy stage policy. Existing `parse`, `parse_with_decimal` and model
JSON APIs preserve strict native behavior. Legacy LaTeX errors refer to caller input; `grammar_byte_offset()` retains the
preprocessed position. Slices reference `Parsed::parsed_input`.
LaTeX keeps the frozen producer's strict native/farthest-failure policy.
Annotated legacy preprocessing carries origin spans through entity, space and
text/mbox rewrites. Strict native/model APIs retain their existing preprocessing.

## WebAssembly

The optional `wasm` feature exports `StageParser` through wasm-bindgen and
enables the existing generated model codecs. Native default features are unchanged.
Build a local Node package (requires wasm-pack 0.13.1 and the WASM Rust target):

```sh
wasm-pack build --target nodejs --out-dir wasm-node --no-opt -- --locked --features wasm
```

```js
const { StageParser } = require('./wasm-node/latexmath.js');
const parser = new StageParser();
try {
  const modelJson = parser.parse("\\alpha+1", '.');
  const rawJson = parser.parseRaw("\\alpha+1", '.');
  const serializedJson = parser.serialize(modelJson);
} finally {
  parser.free();
}
```

`parse` returns portable model JSON using the native strict parser policy.
`parseRaw` returns JSON with `preprocessed` and a canonical tagged `tree`,
including the existing byte and character offsets. Pass `'.'` or `','` as
the decimal option. `serialize` reads and validates portable model JSON and
writes it through the generated codec; empty members may be omitted, as on
the native surface. It does not write source notation. Errors throw strings
containing the native parser or codec diagnostic.

For a browser module, build with `--target web --out-dir wasm-web` and initialize
the generated module before constructing `StageParser`. The WASM workflow builds
both packages, executes a Node smoke against three frozen plurimath-testsuite
raw rows and five native byte references, and uploads `stage-wasm-node-web`.
It does not publish to npm. The smoke also checks decimal options, empty input,
invalid models, parse refusals and parser reuse; it is not a full WASM conformance
or browser-runtime claim.
