# latexmath Rust raw parser

Local unpublished Rust package using the upstream shared PARG artifact and declared
Rust bindings; no handwritten grammar. `Parser::new()` verifies embedded checksums.

```rust
let parser = latexmath::Parser::new()?;
let parsed = parser.parse("x+1")?;
println!("{}", parsed.canonical());
# Ok::<(), latexmath::Error>(())
```

`parse_with_decimal(input, decimal)` accepts `.`, `,`, and `٫`. The native
Parsanol engine is pinned to 0.20.7. Unicode preprocessing and stage transforms
are reused from the pinned shared testsuite, with attribution in UPSTREAM.json.
Errors preserve the native error and expose UTF-8 byte offsets relative to the
preprocessed grammar input. Parsed slices reference `parsed_input`; caller offsets
are not inferred after preprocessing. Canonical output includes character offsets.

The default API exposes raw stage trees and bound JSON. Optional `models` uses
33 types and JSON codecs generated by the existing upstream Lutaml Rust
PR #8 generator. `Parser::parse_model(input, decimal)` and
`typed::to_portable_json(model)` are implemented; their native construction and version-1 C ABI were exercised with focused local checks. Optional `ffi`
exports the stage-specific version-1 C ABI declared in `include/latexmath.h` for
portable model JSON consumers. The ABI returns portable model JSON and structured errors; free each result once as documented in the header.

No full typed parity, Plurimath facade or math-writer coverage is claimed.
Raw and typed verification are assessed separately.
Use `cargo run --example parse -- 'x+1'` for the raw API and
`cargo run --features models --example model -- 'x+1'` for typed models once built.

Native refusal offsets use the Rust engine's farthest-error position and may differ
from Ruby's deepest-error selection. Offsets refer to the preprocessed grammar
input; caller-coordinate remapping is not inferred.

The declared writer omits empty/nil members. Model identity and wire idempotence
across JSON read/write are not guaranteed; cross-runtime model equivalence remains
a separate verification boundary.
